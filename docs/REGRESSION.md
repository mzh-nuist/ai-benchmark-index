# 重点：测模型有没有“降智”

这里的“降智”指**同一受控条件下，某条服务链路的任务表现持续退步**。目录中的“优先”是我们对回归检查适用性的判断，不是原作者认证，也不代表这些题已经证明某个模型退步。

## 先试哪几个

| 你遇到的现象 | 优先测试 | 看什么 |
| --- | --- | --- |
| 连明确要求也不照做 | 定点改字、机器人局部维修、IFEval | 内容正确率与格式正确率分开；有没有误改其他字段 |
| 顺着错误说法瞎答 | 时间纠错、齿轮正反对照、GSM-Symbolic | 计算是否正确、能否拒绝错误前提，别只挑陷阱题 |
| 聊几轮就忘了或用旧条件 | 出游记忆、怪物合租、LongBench / RULER | 有效条件召回、撤销条件是否仍被使用、最终方案是否可行 |
| 开始编人名、时间和出处 | 会议未知项、冲突纪要、SimpleQA | 可证实错误和无依据补充；不要因换一个同义词就判成幻觉 |
| 看图总靠常识猜 | VLMBias、IllusionBench+、MindTopo、MET-Bench | 标准图和反常图成对，图像尺寸一致；答案要能从图中验证 |
| 计划说得漂亮却执行失败 | 推老板、齿轮最小修复、固定种子 Reasoning Gym | 引擎判终态与合法性，不能要求参考答案逐字相同 |

洗车和简单加法可作快速冒烟检查，但有天花板且容易记忆。鹈鹕、斑马更适合展示作品，人工评分噪声较大。账单参考存在歧义，**不纳入核心回归结论**。小卖部、厨房、拆弹等放到长任务专项。

## 怎么才能比较

1. **冻结基线。** 记录真实服务商、请求模型 ID／快照、请求与响应时间、API 路径、系统提示、工具权限、思考档位、采样参数、输出上限、输入图片／上下文和版本哈希。不同厂商的 `high` 不能当成相同算力。
2. **先查服务有没有变。** 工具失效、历史没传全、图片没传到、输出截断、联网失败、限流和网络变慢都单独记录。若换了路由、版本或工具，只能比较整条服务链路，不能直接归因为“底层模型偷偷缩水”。
3. **固定一组题，做成对复测。** 首轮建议六个方向每类至少三道独立变体，共18题，每题每条件三次，即54次／条件；这是起步建议，不是统计充分性的保证。比较两个条件总计108次；按预算缩小时须明确样本不足。多轮题一次试验可能发出多条请求。
4. **交错运行。** 若两个接口都可用，同一时间段交错 A/B，题序随机；保留随机种子。不根据模型回答重写答案。不对每个模型挑最好的那次。
5. **拆开分数。** 内容0–1、格式0–1、完整交付0–1各自报告；图形按冻结量表另评。失败进入交付分母；无法检查内容时保留空分和覆盖率，不能用空分或格式错误伪装成推理错误。
6. **报告变化和不确定性。** 列出基线→当前、样本数、题目覆盖、完整交付率、每题胜／负／平，以及错误类型。正式结论采用按独立题目聚类的配对 bootstrap 或合适配对检验；同一道题重复三次不是三个独立题目。小样本只说“发现退步信号，需复测”，不用任意百分比当科学阈值。
7. **留验证集。** 本仓库都是公开开发材料，可能污染训练。实际监测另生成未公开、同难度的新变体，并冻结生成器版本、种子和答案。新变体成绩不能和老版历史总分直接相加。

## 成本和时间

此仓库不发模型请求、不绑定账户、不充值。索引中的轻／中／重表示部署和流程复杂度，不是已测 token 用量。真正成本取决于请求数、图片、输入、可见输出、隐藏推理、工具、重试及价格；最大输出量不是必定消费量，但硬预算仍须给单次在途请求留出可承受的上界。

TPS、首字耗时、总耗时、输出截断率分别记录。输出更快、字更少不自动说明降智；正文 TPS 不应把推理 token 当作正文。模型裁判若不可避免，要固定裁判版本／提示并标注其费用和误差，用人工抽检或真实环境验证补充。

## 记录模板

使用 [templates/run-record.json](../templates/run-record.json) 记录一次试验，使用 [templates/comparison.md](../templates/comparison.md) 写结论。模板中的空值是待填项，不是零分。本仓库没有生成新的模型成绩。
